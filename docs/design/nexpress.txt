NexPress 기획서 v3 — 핵심 결정

2026-04-17 원본 기획의 역사적 요약이다. 상세 초안과 중복 요약본은 Git
기록에 보존되어 있다. 당시 일정, API 예시, 경쟁 제품 평가는 현재의 제품
상태나 구현 약속으로 읽지 않는다. 현재 사용법은 docs/README.md,
구현 구조는 docs/agent-guidance/reference/root.md를 따른다.

1. 제품 방향

Next.js 기반의 self-hosted CMS로 콘텐츠 저장뿐 아니라 사이트 작성과
운영을 돕는다. 개발자가 확장 가능한 구조와 비개발자용 Admin 경험을
함께 제공하고, 사람과 외부 에이전트가 같은 CMS 기능을 사용하게 한다.

원본의 “Payload는 개발자를 위한 프레임워크, NexPress는 운영자를 위한
제품”이라는 문장은 운영 UX에 집중하려는 당시 포지셔닝이다. 현재 다른
제품의 능력을 비교하거나 평가하는 근거는 아니다.

2. 핵심 아키텍처 결정

- Code-first 컬렉션 정의를 스키마, 검증, 타입, Admin의 공통 입력으로 쓴다.
- PostgreSQL과 Drizzle을 사용하며 변경은 코드 생성과 검토된 마이그레이션을 거친다.
- 리치 텍스트와 페이지 블록 조합을 구분하고 재사용 가능한 블록을 제공한다.
- 테마는 CSS custom properties와 cascade layers를 중심으로 구성한다.
- 플러그인은 신뢰한 npm 패키지로 설치하고 애플리케이션과 함께 빌드한다.
- 초기 플러그인은 프로세스 안에서 실행된다. 권한 선언은 샌드박스가 아니다.
- CMS는 선언적 인터페이스를 제공하고 외부 에이전트가 모델 추론을 수행한다.
- 재사용 패키지와 참조 앱을 분리하며 scaffold가 프레임워크 내부를 복제하지 않게 한다.

현재의 세부 계약은 다음 문서가 소유한다.

- 컬렉션: docs/collection-documents.md
- 편집 데이터: docs/rich-text.md, docs/block-content.md
- 테마: docs/theme-authoring.md, docs/theme-tokens.md
- 플러그인: docs/plugin-quickstart.md, docs/plugin-capabilities.md, docs/plugin-admin.md
- 에이전트: docs/agent-integration.md, docs/design/agentic-platform/README.md
- 설치와 운영: docs/site-customization.md, docs/deployment.md

3. 초기 범위와 순서

먼저 설치, 로그인, 작성, 미리보기, 발행이 이어지는 블로그 CMS를 만들고,
그 위에 페이지 조합, 테마, 플러그인, 에이전트 인터페이스를 확장하려 했다.
WordPress 콘텐츠/미디어 이전은 기존 사이트가 실제로 옮겨올 수 있게 하는
주요 제품 요구였다. 현재 이전 방법은 docs/wordpress-import-guide.md에 있다.

초기 주차별 일정과 단계 번호는 현재 작업 순서가 아니다. 특히 격리
플러그인 런타임은 장기 연구 후보였으며 초기 제품이 제공하는 보장이 아니었다.

4. 남겨야 할 범위 제한

자유형 빌더나 범용 AI 실행기를 먼저 만드는 대신 제한된 조합과 명시적
인터페이스로 시작한다. 플러그인 설치는 신뢰 결정이며, 향후 격리는 별도
검증이 필요하다. 운영 편의성은 실제 설치·작성·발행 흐름으로 확인한다.
현재 Agent Platform의 호스트 주입, 권한, 자격 증명, 승인 및 수용 기준은
해당 구현 문서가 정의한다. 이 기획 요약으로 그 경계를 넓히지 않는다.
